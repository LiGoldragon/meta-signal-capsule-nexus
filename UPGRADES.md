# Upgrades

## 0.5.0 — 1.0.0 and 1.0.1 renumbered to the 0.x line

A breaking change on a 0.x crate takes the next minor, so the contract published as 1.0.0 and
1.0.1 is renumbered 0.5.0. The contract, its archive, its digest and its Datom text are those of
1.0.1 (76b4235); only the version moves. 1.0.0 and 1.0.1 were never deployed and leave the build
base's registry. A consumer pins 0.5.0 at its new commit in place of 1.0.1.

## 1.0.1 — signal 11.2.0, translator 0.5.2

Only the pins move: signal 11.2.0 (4f5cbb9), which adds `signal::Following`, and translator 0.5.2 (29601a3), which takes it. No type, archive or digest of this contract changes. A consumer repins both with it, so `links = "signal"` finds one package in its graph.

## 1.0.0 — ethos-zero 30.0.0, signal 11.1.0, translator 0.5.1

The contract is regenerated by ethos-zero 30.0.0 (b97d952), the generator its `generated` check pins, and signal moves to 11.1.0 (b145ddb) with translator 0.5.1 (2310db3), which takes the same signal. Datom-codec 09a0526 and protos c93b598 stay. The authored ethos is unchanged.

- `Query` is `Input` and `Response` is `Output`, as every Signal names them since ethos-zero 26.0.0. The file also generates `Answering`, with the one capability `configure`, and `Answerable`, whose `type Answer` is `Output`. Every type is as before, so the rkyv archive and the Datom text are unchanged.

To deploy: rename `Query` and `Response` to `Input` and `Output`; then repin meta-signal-capsule-nexus 1.0.0 with signal 11.1.0 and translator 0.5.1.

## 0.4.1 — translator unix

The translator dependency turns on its `unix` feature, which attaches libc and nix: the edge the build base's feature set asks of a repository that builds translator. No change to the authored ethos, the generated Rust, the archive or the Datom text. The feature leaves this manifest when `unix` becomes a crate of its own.

## 0.2.1 — translator 0.3.1

Repins translator 0.3.1 (`1b0e`), up from 0.3.0 (`eeaa`), so a consumer that also calls translator's start-time place preparation holds one translator in its lock. The contract uses only `translator::PeerBinding` and `translator::PeerId`, whose shapes are unchanged. The authored `signal.ethos`, the generated types and the archive layout are unchanged.

## 0.2.0 — signal 10.3.0, datom-codec 0.33.0, protos 0.33.0, translator 0.3.0

Repins signal 10.3.0 (7afb), datom-codec 0.33.0 (eabe), protos 0.33.0 (3c7a) and translator 0.3.0 (eeaa), each spelled as translator spells them so the lock holds one source of each. The translator moves from 0.2.0 (7078); the contract uses only `translator::PeerBinding` and `translator::PeerId`, whose shapes are unchanged.

- The generated contract is regenerated with ethos-zero 19.2.0 (5a5d), the flake's generator input now the bare URL with the lock pinning it. The authored `signal.ethos` is unchanged; the generated types add `PartialOrd` and `Ord` (and `Copy` where the scalar is `Copy`). No type, variant or field changes, and the rkyv layout is unchanged.
- protos 0.33.0 prints a balanced guillemet pair inside a string without an escape; a consumer holding datom text with an unbalanced guillemet re-reads it.
- The flake keeps its `generated` and `test` checks and gains `test-default` and `test-datom`. `tests/contract.rs` archives and restores a query and a response in every build, and under `datom` reads, prints and refuses wrong shapes for the configure and response forms.

To deploy: repin meta-signal-capsule-nexus 0.2.0 in the consumer, with the same translator revision.
